# Ponytail UI / Code Review

## UI 방향 점검

- Paper / Ink / Plum / Vermilion / Ochre / Lavender 토큰과 Serif / Sans / Mono 역할을 유지합니다.
- 홈의 C → B → A SVG, 표본 서가, 줄노트 다이어리, OWNER 기록지, 프로젝트 상세의 종이 프레임과 캡션 구조가 동일한 아카이브 언어를 사용합니다.
- 상속길잡이의 실제 서비스 화면은 원본 그대로 유지하고, 사이트의 종이 프레임과 설명 캡션 안에 전시합니다. 제품 화면 자체를 포트폴리오 테마로 덧칠하지 않습니다.
- 브라우저 렌더링은 현재 실행 환경의 관리자 정책으로 열 수 없어 시각적 픽셀 검증은 하지 않았습니다. 이 평가는 최종 HTML/CSS 구조와 제공된 실제 캡처를 기준으로 합니다.

## 정리한 코드

- 10개의 `<style>` 블록을 cascade 순서를 보존한 단일 블록으로 통합했습니다.
- `build_projects.py`가 프로젝트 CSS를 안정된 삽입 지점에 넣도록 수정했습니다.
- 모바일 보정 CSS를 별도 `<style>`로 추가하지 않고, 하나의 스타일 블록 안에서 marker 구간만 교체하도록 수정했습니다.
- 중복 `.ed-project-toc button` 규칙을 하나로 합쳤습니다.
- 뒤에서 완전히 덮이던 구형 `.project-map` 컨테이너·캡션·노트 선언과 중복 overview 선언을 제거했습니다.
- GitHub Actions의 항상 참인 push 조건을 제거했습니다.
- 포스트 존재 확인에서 `README.md`를 제외해 문서 파일만 있을 때 빌드/배포하지 않도록 수정했습니다.

## 검증

- CSS: 단일 style 블록, 파싱 오류 0
- HTML: 중복 ID 0
- 로컬 이미지: 누락 0
- 프로젝트 템플릿: 6개
- 상속길잡이 갤러리: 실제 캡처 4개 경로 포함
- JavaScript: `node --check` 통과
- Python 빌더: 컴파일 통과
- 프로젝트/블로그 빌더 연속 실행 후 `index.html` SHA-256 동일
- GitHub Actions YAML 파싱 가능, 수동 실행 없음, README 제외 조건 확인
- 전체 테스트 스위트는 사용자의 이전 지시에 따라 Actions에서 실행하지 않으며, 이번에도 전체 테스트 스위트는 실행하지 않았습니다.

## 의도적으로 남긴 것

- Pygments는 코드 블록 하이라이팅에 실제 사용하므로 유지합니다.
- 프로젝트/블로그 빌더는 각 콘텐츠 유형의 독립적인 생성 책임을 유지합니다.
- Phase별 CSS 구간은 스타일 태그를 분리하지 않고 주석으로만 구분합니다.
