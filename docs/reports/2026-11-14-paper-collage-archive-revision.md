# Paper Collage Archive — 수정 결과 보고서

## 핵심 발견

`02 — Paper Collage Archive`를 단일 메인 페이지로 승격하고 `01` 시안을 제거했다. 기존 프로젝트와 다이어리 원고는 바꾸지 않았으며, 빌드 경로·사이드바·아카이브 시각 언어·반응형 및 키보드 기본 구조를 함께 정리했다.

## 범위와 완료 기준

- 대상: 정적 HTML 개인 웹 아카이브.
- 목적: 취업용 전환이 아닌 개인의 취향과 작업 흔적을 보관하는 단일 아카이브.
- 성공 기준: 루트 직접 진입, 02 디자인 단일화, 01 파일 제거, 기존 콘텐츠 보존, 반복 빌드 안정성, 반응형/접근성 기본 구조.
- 제외: 새 프로젝트·소개·연락처·이력서·기술 스택 추가, PDF 제작, 공개 배포.

## 빌드 중 발견한 문제와 조치

첫 반복 빌드 비교에서 프로젝트 라우터 훅 앞에 빈 줄이 한 줄씩 누적됐다. 원인은 훅 문자열만 제거하고 주변 공백을 보존한 뒤 다시 삽입하는 방식이었다. 라우트 훅과 그 공백 슬롯을 함께 정규화하도록 수정했다.

수정 후 `build_projects.py`와 `build_blog.py`를 연속 두 번 실행해 생성된 `index.html`의 SHA-256이 동일함을 확인했다.

## 검증하지 못한 범위와 위험

Chromium 실행은 현재 컨테이너 정책에서 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단됐다. 따라서 실제 브라우저의 렌더링, 터치, 뒤로 가기, 키보드 및 스크린리더 실사용 테스트는 완료했다고 주장하지 않는다.

WeasyPrint로 정적 화면 미리보기를 확인했지만, 이 렌더러는 브라우저의 JavaScript와 SVG CSS 애니메이션을 실행하지 않으므로 실제 인터랙션 검증의 대체물이 아니다. CSS/DOM 정적 검사와 JavaScript 구문 검사는 통과했으나, 배포 전 실제 브라우저에서 320px·390px·데스크톱, 프로젝트/다이어리 직접 진입, reduced-motion, 키보드 탐색을 확인할 필요가 있다.

## 재사용 가능한 교훈

1. 단일 정적 페이지에 여러 빌더가 쓰는 경우, 출력 대상과 삽입 위치를 하나의 명시적 계약으로 유지한다.
2. 생성 코드의 멱등성은 파일 전체 해시 비교로 확인한다. 문자열만 제거하고 재삽입하면 공백도 누적될 수 있다.
3. 아카이브의 개성은 콘텐츠를 늘리는 방식보다, 이미 있는 기록을 읽는 표면과 탐색 경험을 정교하게 만드는 방식으로 강화할 수 있다.
