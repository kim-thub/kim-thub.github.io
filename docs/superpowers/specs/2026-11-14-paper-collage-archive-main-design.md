# Paper Collage Archive — 단일 메인 페이지 전환 및 전체 리파인

## 의도

이 사이트를 취업용 포트폴리오나 시안 선택기가 아닌, 개인의 취향과 작업 흔적이 쌓이는 독립적인 웹 아카이브로 완성한다. 사용자가 선택한 `02 — Paper Collage Archive`를 유일한 디자인 방향이자 공개 진입점으로 삼는다.

## 목표

1. 루트 `index.html`에서 Paper Collage Archive가 바로 열린다.
2. `01-diff-reader.html`을 제거하고 `02-paper-collage.html`을 별도 진입점으로 유지하지 않는다.
3. 프로젝트 상세 6개와 다이어리 7개, 기존 사실·수치·개인 기여 범위는 보존한다.
4. 종이·표본·인쇄물·비대칭 콜라주라는 시각 언어를 색상, 서체, 여백, 레이어, 인터랙션 전반에 일관되게 적용한다.
5. C → B → A 시그니처 변환은 유지하고, 첫 화면의 시각적 완성도와 기억성을 높인다.
6. 프로젝트 서가·기술 다이어리·About의 탐색 흐름을 정돈하고 작은 상호작용에 일관성을 준다.
7. 320px부터 데스크톱까지 리플로우, 키보드 탐색, 포커스 표시, 모션 감소 설정을 지원한다.
8. 두 Python 빌더가 단일 `index.html`만 갱신하며 반복 실행해도 결과가 누적·손상되지 않는다.

## 비목표

- 취업 전환율을 위한 연락처, 이력서, 기술 스택, 성과 대시보드 추가.
- 프로젝트·글·프로필 콘텐츠의 양을 늘리는 작업.
- PDF 포트폴리오 제작.
- 01 디자인과 02 디자인을 혼합하거나 01의 시각 요소를 가져오는 작업.
- 외부 폰트, 이미지, 애니메이션, 사운드 라이브러리 추가.
- 공개 배포, GitHub Pages 게시, 원격 저장소 푸시.
- 프로젝트의 사실·지표·기여 범위 변경.

## 현재 구조와 확인된 문제

- `index.html`은 두 시안을 고르는 선택 화면이다.
- `01-diff-reader.html`과 `02-paper-collage.html`이 독립 HTML로 중복되어 있고 두 빌더가 모두를 대상으로 한다.
- 02의 사이드바 마크업에 정규식 역참조 문자열 `\\1`, `\\2`가 문자 그대로 남아 있다.
- 02의 스크립트에 현재 화면에 없는 게임 라우트/벽돌깨기 코드와 01·미니홈피용 분기가 남아 있다.
- 02의 스타일에는 초기 팔레트와 여러 방향별 오버라이드가 중복되어 있어 최종 디자인 토큰을 읽기 어렵다.
- 현재 C → B → A SVG 변환과 `prefers-reduced-motion` 최종 형태 처리는 이미 존재하므로 이를 교체하지 않고 다듬는다.

## 접근 방식과 선택

### 진입 구조

- 선택지 A: 02 파일을 유지하고 `index.html`에서 리다이렉트한다. 원본 파일을 덜 건드리지만 중복 진입점과 불필요한 경로가 남는다.
- 선택지 B: 02를 `index.html`로 통합하고 01·02 별도 파일을 제거한다. 루트가 실제 사이트가 되고 빌더도 한 페이지를 대상으로 단순해진다.
- **선택: B.** 사용자가 02를 메인으로 확정하고 01 제거를 요청했다. 별도 시안 파일을 유지할 이유가 없다.

### 디자인 리파인

- 선택지 A: 기존 CSS를 전면 재작성한다. 정리는 쉽지만 기존 프로젝트/다이어리 레이아웃과 복잡한 도식이 깨질 위험이 크다.
- 선택지 B: 기존 읽기 레이아웃과 도식 스타일은 보존하고, 중복 토큰을 단일 팔레트로 정리한 뒤 아카이브 전용 규칙을 한곳에 둔다. 불필요한 01·미니홈피 분기만 제거한다.
- **선택: B.** 기존 콘텐츠와 읽기 구조를 보존하면서 디자인 완성도를 올리는 가장 작은 변경이다.

### 인터랙션과 접근성

- 선택지 A: 애니메이션과 JS 위젯을 추가한다. 눈에 띄지만 의존성과 자극이 늘어난다.
- 선택지 B: 기존 CSS/SVG 애니메이션, 링크, 네이티브 HTML을 정돈한다. 키보드·포커스·모션 감소·좁은 화면을 함께 검증한다.
- **선택: B.** 외부 의존성 없이 기존 시그니처를 강화한다.

## 제약과 불변 조건

- Python 빌드: `scripts/build_projects.py`, `scripts/build_blog.py`.
- 프로젝트 원고: `content/projects/*.html`.
- 다이어리 원고: `content/first-post.md`, `content/posts/*.md`.
- 외부 의존성 추가 금지. 기존 Pygments 빌드 의존성은 유지한다.
- 모든 프로젝트/글 slug와 해시 라우팅을 유지한다.
- 기존 수치·날짜·단위·검증 범위·한계·역할을 바꾸지 않는다.
- 원본 ZIP을 덮어쓰지 않고 별도 작업본을 만든다.

## 완료 기준

- 루트 `index.html`이 바로 Paper Collage Archive를 렌더링하는 단일 진입점이다.
- `01-diff-reader.html`, `02-paper-collage.html`이 작업본에 남아 있지 않다.
- 사이드바의 실제 `aside/nav` 구조가 있고 `\\1`, `\\2`가 출력되지 않는다.
- 빌더가 `index.html`만 갱신하며 연속 실행 후에도 중복 스타일/목차/블로그 데이터가 늘지 않는다.
- 프로젝트 6개와 글 7개, 내부 해시 경로, 로컬 이미지 경로가 보존된다.
- 320/360/390/430px 및 데스크톱에서 페이지 폭이 뷰포트보다 커지지 않도록 CSS/DOM을 점검한다.
- `prefers-reduced-motion`, 키보드 포커스, 본문 건너뛰기 링크를 제공한다.
- Python 컴파일, 빌드, HTML 구조 검사, 인라인 JavaScript 구문 검사가 통과한다.
- 브라우저 실사용 검증을 실행할 수 없으면 그 한계를 완료 보고서에 명시한다.

## 검증 경계

정적 검사와 빌드 검증은 자동으로 수행한다. 현재 실행 환경에서 Chromium이 관리자 정책으로 차단되면 실제 브라우저 렌더링·터치·스크린리더 검증을 완료했다고 주장하지 않는다.
