Webtoon Feedback

한 편의 이야기가 독자에게 닿은 뒤에는 저마다 다른 반응이 남습니다. 댓글과 별점 사이에 흩어진 감상을 분석하고, 생성형 피드백으로 정리해 작가가 독자의 반응을 되짚어 볼 수 있도록 했습니다.

프로젝트 개요

댓글과 별점이 쌓일수록 작가가 독자의 반응을 일일이 살펴보고 공통된 의견을 파악하기는 어려워집니다. Webtoon Feedback은 수집된 댓글의 감성을 분석하고 비슷한 의견을 묶어 보여줍니다. 이를 바탕으로 Gemini가 피드백을 생성하고, 결과를 저장해 작가가 언제든 다시 살펴볼 수 있도록 했습니다.

서비스 기능

  • 작품 관리

    분석할 웹툰을 등록하고 목록에서 제거합니다.

  • 댓글 반응 분석

    댓글을 라벨과 감성, 유사도 기준으로 분류해 작품에 대한 반응을 살펴봅니다.

  • 피드백 저장

    분석 결과를 바탕으로 Gemini 피드백을 만들고 PocketBase에 저장합니다.

시스템 구조

화면 자료

실행 중인 화면 캡처입니다. 기획과 팀 산출물은 프로젝트 문서에서 확인할 수 있습니다.

제가 맡은 일

팀 리더로 일정과 기능 범위를 조율했습니다. 화면 구현과 댓글 수집용 크롤러는 다른 팀원이 맡았으며, 저는 Flask를 기반으로 댓글 분석부터 Gemini 피드백 생성, PocketBase 저장까지 이어지는 서비스 흐름을 구현했습니다.

화면 집계와 생성형 피드백의 기준을 맞춤

분석 대상에서 제외해야 하는 라벨 4 댓글이 화면 집계나 Gemini 입력에 포함되면, 화면에 표시한 분석 결과와 생성된 피드백이 서로 다른 댓글을 기준으로 작성될 수 있었습니다.

두 경로에서 같은 제외 기준을 적용했고, 이미 처리한 최신 회차는 다시 분석하지 않도록 정리했습니다.

수정 코드와 수동 확인 범위는 분석 파이프라인 기록에서 확인할 수 있습니다.

확인된 범위

웹툰 등록·삭제, 분석 화면 이동, NLP 결과 생성, PocketBase 저장을 직접 실행해 확인했습니다.
