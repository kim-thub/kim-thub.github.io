TicketFlow

인기 공연의 예매가 열리면 접속자가 한꺼번에 몰려 사이트가 느려지거나 접속이 끊기기도 합니다. TicketFlow는 이런 티켓 예매 환경을 재현하면서 고동시성 시스템을 직접 구현하고 검증해 보려고 시작한 개인 프로젝트입니다. 대기 순서를 지키면서 입장을 허용하고, 같은 좌석이 두 번 예약되지 않도록 구현했습니다.

프로젝트 개요

사용자가 몰릴 때 대기열이 입장을 어떻게 제어하는지, 여러 요청이 같은 좌석을 차지하려 할 때 데이터베이스가 어떤 결과를 남기는지 확인하고 싶었습니다. 공연 탐색부터 대기열, 좌석 선택, 결제, 발권과 환불까지 한 흐름으로 연결했습니다.

결제 뒤 Worker가 멈추거나 응답이 유실돼 재시도해도 예약과 발권 상태가 어긋나지 않도록 각 처리의 책임과 저장 경계를 나눴습니다.

예매 흐름

주요 기능

  • 선착순 대기열 — Redis에서 FIFO 순서와 입장 토큰을 관리하고 허용률과 활성 세션 수를 제한합니다.
  • 좌석 선점과 멱등성 — PostgreSQL의 행 잠금과 활성 예약 제약으로 중복 선점을 막고 같은 요청에는 기존 결과를 돌려줍니다.
  • 결제 후처리 — DB 트랜잭션에 결제 상태와 이벤트를 함께 기록한 뒤 Kafka Worker에서 발권과 환불을 처리합니다.
  • 모니터링과 부하 확인 — Prometheus와 Grafana에서 HTTP 지연, 대기열, DB 연결 풀을 보고 k6로 부하를 발생시킵니다.
  • 실패·재시도 처리 — 입장 응답 유실, 좌석 충돌, Worker 재시작 상황에서 기존 토큰과 기록을 대조해 상태를 확인합니다.
